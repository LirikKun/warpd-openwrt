# warpd

[English](README.md)

Панель управления WARP-прокси для OpenWrt: поиск эндпоинтов, динамические SOCKS-профили, проверки доступности и английский/русский веб-интерфейс. Один общий процесс Mihomo обслуживает туннельные профили; WarpScout отвечает за поиск и регистрацию аккаунта. TUN, маршруты, правила firewall и прозрачное перенаправление не добавляются. SSClash не требуется, его файлы не заменяются.

> **Область версии:** README описывает **кандидат 3.0.0 в исходниках**, а не развёрнутую или готовую к выпуску сборку. Офлайн-ревью пройдено; приёмка в реальной сети ещё необходима. Инструкции скачивания ниже устанавливают **предыдущий опубликованный релиз v2.2.0**, **не** динамические профили и TCP-шлюзы кандидата. Ссылки на скачивание релиза v3 здесь не заявлены.

> **Граница безопасности:** сохранённое включение, доступность движка, готовность политики и публичный порт — разные состояния. Публичные порты кандидата принимают только TCP SOCKS5 CONNECT после свежей проверки конкретного управляемого процесса, применённой конфигурации/поколения и наблюдаемой политики выхода. Relay-WARP дополнительно требует свежей независимой проверки иностранного выхода. Эти проверки **не** подтверждают привязку у провайдера или расположение туннельного пира. Интегрированная реализация Relay проверена офлайн, но не прошла реальную приёмку провайдера/туннеля; подмены прямым WARP нет.

## Возможности и статус кандидата

- Несколько профилей WARP / AmneziaWG и MASQUE, у каждого стабильный ID, имя, порт, закреплённый эндпоинт, состояние проверок и дополнительные исключения. MASQUE поддерживает `quic` и `http2` (H2).
- Создание, редактирование и удаление через панель/API; тип неизменяемый. Профили и ресурсы Relay хранятся приватно, а не в четырёх фиксированных слотах UCI.
- Чистая инициализация кандидата создаёт **только один профиль WARP**, с намерением включения на порту 4001. Остальные добавляются явно. Существующее пустое хранилище остаётся пустым, в том числе для одного мониторинга.
- Старые фиксированные секции мигрируют, включая выключенные. Существующая цепочка MASQUE → WARP сохраняется как **`legacy-m2w`**, только при миграции: можно переименовать, включить/выключить или удалить; туннельные параметры доступны лишь для чтения. **Создавать новые цепочки нельзя.**
- Автопоиск, закрепление эндпоинтов и ограничение частоты повторных поисков. Проверяемые SOCKS-порты движка слушают только приватный loopback.
- Публичные TCP-шлюзы самого приложения закрывают порт **и уже принятые потоки** при отзыве или истечении допуска. UDP ASSOCIATE и BIND не поддерживаются.
- Независимый мониторинг IP Relay и запросы активации без WARP-аккаунта и запущенного движка в режиме одного мониторинга. **Совместимость провайдера/туннеля не подтверждена.**
- Встроенная панель без CDN, внешних шрифтов и Node.js на роутере. Без фактически включённых туннельных профилей движок может остановиться, управление остаётся доступным.

Основания в исходниках: [интеграция ядра](docs/core-integration.md), [рабочий контракт API](docs/profile-api-contract.md), [хранилище](profile_store.go), [валидация](profile_validation.go), [API](profile_api.go), [TCP-шлюзы](profile_gate.go). Рабочий контракт не гарантирует наличие возможностей в опубликованном релизе.

## Требования

- OpenWrt с procd и UCI, Linux `arm64` или `amd64`. Кандидату ещё нужна разрешённая приёмка на роутере; локальные тесты не демонстрируют рабочий туннель.
- Доступ root по SSH, свободные выбранные порты и достаточно места в overlay и `/tmp` для распаковки архива. На OpenWrt `/tmp` занимает RAM. Движок Mihomo — самая большая часть комплекта; установщик проверяет свободное место.
- Системное хранилище доверенных CA (`ca-bundle` или эквивалент) и правильные дата/время для HTTPS. Bootstrap предлагает установить поддерживаемые недостающие пакеты после согласия, используя существующие репозитории; feeds не меняются.
- Доступ к инфраструктуре Cloudflare для регистрации/туннелей и к HTTPS-сервисам проверок.
- Для первоначального скачивания скрипта по инструкции ниже нужен `wget` с работающей проверкой HTTPS-сертификатов. Для файлов релиза bootstrap требует `curl` (при отсутствии предлагает установить его через тот же запрос согласия): общий лимит каждой попытки — 180 секунд, не более трёх попыток на файл. Для распаковки нужен `tar` с поддержкой gzip. Не отключайте проверку TLS при ошибках скачивания.
- Для установщика нужны `/bin/sh` и команды `sha256sum`, `cat`, `cp`, `mv`, `chmod`, `mkdir`, `dirname`, `uname`, `id`, `readlink`, `grep`, `wc`, `ls`, `df`, `awk`, `mktemp`, `rm`, `rmdir`, `ln`, `sleep` (обычно доступны через BusyBox), а на роутере также `uci`. Размеры файлов проверяются через `wc -c`, права каталога для отката — через `ls -nd` и `awk`; bootstrap также проверяет `date`, `tar`, `gzip`, `procd`, `ubus`, `jsonfilter`, procd-скрипты и CA bundle. Поддерживаемые недостающие пакеты предлагается установить через `apk`/`opkg`; базовые утилиты повреждённой прошивки нужно восстановить явно.

Установочный комплект содержит warpd и закреплённые версии WarpScout 0.16.0 и Mihomo 1.19.31. Сторонние компоненты устанавливаются в отдельный каталог warpd, а не поверх бинарников SSClash. Источники и лицензии: [THIRD_PARTY.md](THIRD_PARTY.md).

## Установка — только предыдущий опубликованный v2.2.0

**Этот раздел устанавливает v2.2.0, не кандидат 3.0.0 из исходников.** В v2.2.0 используется старая модель фиксированных слотов и рекомендательная оценка политики выхода; не считайте его публичные SOCKS-порты защищёнными TCP-шлюзами кандидата. Не используйте эти команды для отката установленного кандидата на старую версию.

### 1. Скачать и установить предыдущий релиз

Подключитесь по SSH как root, заменив адрес своим:

```sh
ssh root@192.168.10.1
```

Выполните блок ниже. Аккаунт GitHub и токен не нужны. Скрипт сохраняется в приватный временный файл, а не передаётся потоком в оболочку:

```sh
(
  umask 077
  script=$(mktemp /tmp/warpd-setup.XXXXXX) || exit 1
  wget -O "$script" https://github.com/LirikKun/warpd-openwrt/releases/download/v2.2.0/install-warpd.sh &&
    sh "$script"
  result=$?
  rm -f "$script"
  exit "$result"
)
```

Установщик проверяет OpenWrt, права root, архитектуру (`arm64`/`amd64`), свободное место, необходимые команды и CA для HTTPS. Недостающие поддерживаемые зависимости предлагает установить через настроенные репозитории `apk` или `opkg`. Он не обновляет всю систему, не редактирует feeds, сеть, firewall или SSClash и не отключает проверку TLS. Если отсутствует базовый компонент прошивки или пакетный менеджер не может получить зависимости, установка прекращается с объяснением.

В интерактивной установке выберите **English / Русский** для веб-интерфейса. При обновлении текущий язык можно сохранить. Затем скрипт скачивает комплект v2.2.0, проверяет SHA-256 до распаковки и запускает установку с откатом при ошибке замены файлов или запуска службы. Временный каталог очищается автоматически. SHA-256 обнаруживает повреждение, но не заменяет доверие к издателю и HTTPS.

Для автоматизации сохраните скрипт тем же способом и замените строку `sh "$script"` нужным вариантом:

```sh
# Русский интерфейс; разрешить установку недостающих системных пакетов:
sh "$script" --language ru --yes
# Английский интерфейс:
sh "$script" --language en --yes
# Только проверить требования, ничего не устанавливать:
sh "$script" --check-only
```

`--yes` разрешает установку недостающих зависимостей без дополнительного вопроса. Без терминала и такого согласия недостающие пакеты не устанавливаются. Добавленные общие системные пакеты не удаляются при ошибке установки warpd или его последующем удалении.

**Внешние зависимости.** По умолчанию комплект устанавливает свои Mihomo и WarpScout. Если совместимые бинарники уже есть, можно не занимать место второй копией — замените строку запуска следующим вариантом, а не запускайте установку дважды:

```sh
sh "$script" --language ru \
  --mihomo /opt/clash/bin/clash \
  --warpscout /usr/bin/warpscout
```

warpd создаёт свои ссылки на эти файлы, не перезаписывает и не удаляет их. Обновления внешних бинарников их владельцем повлияют и на warpd. Старые Clash могут не поддерживать MASQUE, AmneziaWG и `dialer-proxy`.

**Ручная / офлайн-установка.** Архивы `linux-arm64` и `linux-amd64` и их `.sha256` доступны в [релизе v2.2.0](https://github.com/LirikKun/warpd-openwrt/releases/tag/v2.2.0). Скачайте нужную пару, выполните `sha256sum -c <имя-архива>.sha256` **до распаковки**, распакуйте в приватный временный каталог и запустите `sh install.sh --language ru` из него. Этот внутренний установщик не скачивает системные пакеты: требования должны быть подготовлены заранее. Для переноса с компьютера на Dropbear без SFTP используйте `scp -O`. Удаляйте только свой точный временный каталог после успешной установки.

Это переносимый комплект, не пакет APK/IPK: warpd не регистрируется в `apk`/`opkg` и удаляется собственной командой ниже. Новая установка включает автозапуск; обновление сохраняет настройки, аккаунт и состояние службы.

### 2. Первый запуск предыдущего релиза

Откройте `http://<LAN-IP-роутера>:9095/`. В v2.2.0 по умолчанию включён только WARP; остальные фиксированные сервисы выключены.

На чистой установке аккаунта ещё нет. В панели откройте «Диагностика и журнал» → «Обслуживание аккаунта · опасные действия» → «Новый аккаунт». Подтвердите действие и дождитесь успешной регистрации в журнале. Затем нажмите «Найти для всех», если поиск не начался автоматически. Регистрация и поиск зависят от доступности внешней сети; установленная служба ещё не означает готовый туннель.

Не создавайте новый аккаунт при обычном обновлении: это заменяет общие учётные данные и может прервать соединения всех сервисов.

## Работа с кандидатом 3.0.0 из исходников

Это описание поведения кандидата, **не инструкция по развёртыванию до ревью**. Ссылки на опубликованный установщик v3 здесь нет. Локальная сборка и проверки описаны ниже.

### Профили, миграция и порты

Порт панели/API по умолчанию — 9095. Чистая инициализация создаёт только WARP (ID `warp`, порт 4001, сохранённое включение), а не выключенные карточки MASQUE/H2/цепочки. Добавляйте профили явно; API выдаёт новым профилям непрозрачные стабильные ID и свободный порт, начиная поиск с 4001. Имя и тип — не ID. Порты должны различаться, в том числе у выключенных профилей, и не совпадать с панелью или портом контроллера 9099.

Если хранилища ещё нет, секции профилей UCI мигрируют без перезаписи исходной конфигурации UCI и аккаунта. Сохраняются флаги включения, порты и закреплённые эндпоинты, включая выключенные записи. Миграция сохраняет фактический старый пакет AWG I1 из аккаунта; отсутствие/некорректность необходимых данных вызывает видимую ошибку, а не выдуманные ключи или пакеты. Существующее пустое хранилище определяет пустой набор профилей. Повреждённое, невалидное или неподдерживаемое хранилище сохраняется и отклоняется: управление показывает `profile_error`, работа профилей и поиск блокируются вместо скрытого сброса к настройкам по умолчанию.

После правок готовность обновляется очередным настроенным циклом проверок, не немедленной пробой туннеля внутри CRUD. У включённого, но непроверенного профиля **нет публичного порта**; отказ соединения может быть штатным защитным состоянием.

### Доступ и приватные данные

Адрес управления и желаемый публичный адрес профиля по умолчанию — `0.0.0.0`, API-токен изначально пустой. Это вариант для доверенной LAN с подходящим существующим firewall, **не публикация в Интернет**. WAN-порты не открываются. Ограничьте управление через UCI (`web_listen`), адреса профилей — через API профилей. `warpd.global.web_secret` защищает API, но **не** аутентифицирует SOCKS-клиентов. После внешних изменений адреса/порта/токена управления нужен перезапуск. Межсайтовая защита не заменяет аутентификацию и сетевые ограничения доступа.

Не помещайте токены в URL и не публикуйте аккаунт, `/etc/warpd/profiles.json` или сгенерированный `/tmp/warpd-mihomo.yaml`. URL активации Relay — учётные данные: API принимает их только на запись, хранит в приватном файле, не возвращает в публичных DTO и безопасных статусах/ошибках. Резервные копии тоже должны оставаться приватными.

### Ресурсы Relay, учётные данные и реализация кандидата

Ресурс Relay и дочерние профили `relay-warp` сохраняют намерение включения раздельно. Выключение родителя приостанавливает детей, не меняя их сохранённые флаги; запросы включения/выключения ребёнка блокируются, пока родитель выключен. Удаление ребёнка остаётся доступным. Перед удалением родителя удалите **все** связанные профили, включая выключенные. Одни учётные данные активации нельзя привязать к нескольким ресурсам. Пустое поле существующего URL сохраняет его; это не обход зависимостей.

Мониторинг работает независимо при пустом наборе профилей, без загрузки WARP-аккаунта и запуска Mihomo. Новые ресурсы выключены. Мониторинг/активация требуют исходного IP или интерфейса и явного подтверждения одинакового исходящего пути; запросы ограничены, объединяются и учитывают задержку стабилизации, паузы и лимиты повторов. Включение подтверждённого мониторинга может вызвать запросы провайдеру; не включайте его только ради просмотра настроек.

Туннельные учётные данные Relay-WARP **принадлежат профилю**, отдельно от ресурса активации и общего WARP-аккаунта. Доступны явное подтверждённое создание нового аккаунта для профиля и ручной ввод только на запись: приватный ключ, **серверный `[Peer] PublicKey`** (не публичный ключ клиента), назначенный туннельный IPv4 и необязательный назначенный IPv6, при необходимости совместимые Reserved/DNS/MTU. Адреса проверяются, не выдумываются и не заимствуются у общего аккаунта. Публичный API не возвращает значения учётных данных. Сохранение или генерация записывает их и отзывает старый допуск, но **не** применяет туннель и не активирует Relay. Сохранение, включение, перезапуск и мониторинг никогда не регистрируют аккаунт неявно.

В исходниках кандидата отдельный для каждого профиля UDP-мост на loopback интегрирован с **тем же управляемым процессом Mihomo**: это не второй движок и не замена прямым WARP. Мост привязывает трафик провайдера и DNS к подтверждённым исходному адресу/интерфейсу/семейству и допускает только UDP-сокет конкретного дочернего процесса для применённой конфигурации/поколения. Нужны поддержка Linux pidfd, проверка владельца сокета через `/proc` и права на дублирование его файлового дескриптора; без поддержки или прав доступ закрыт, ослабленного обходного пути нет. Публичный TCP-шлюз по-прежнему требует актуального допуска моста, свежей проверки туннеля и политики выхода, включая независимую проверку иностранного выхода. Сохранение учётных данных, применение движком и публичная готовность — разные результаты; готовность читайте из `/api/status`, не из метаданных действий с аккаунтом.

**Совместимость провайдера/туннеля и реальная приёмка ещё не подтверждены.** Офлайн-фикстуры и диагностика ядра целевого роутера не доказывают рабочий туннель провайдера, привязку или иностранный выход; приложение-кандидат для приёмки не развёрнуто. HTTP 200 провайдера означает неподтверждённый результат активации, не доказанную привязку или готовность туннеля. Подтверждение пользователя и HTTP-наблюдение IP сами по себе не доказывают общий ожидаемый исходящий путь активации и туннельного трафика. Ключи провайдера, назначенные адреса, Reserved/AWG и фактическая эквивалентность пути всё ещё требуют разрешённых реальных проверок. См. [интеграцию Relay и границы доказательств](docs/relay-runtime-integration.md) (англ.).

### Фильтры и совместимость AWG

Эффективные исключения — **объединение** встроенных DME/RU, глобальных списков UCI и списков профиля. Локальные настройки добавляют ограничения; пустые поля не убирают встроенные. Коды узлов — трёхбуквенные коды colo; коды стран валидируются. Неизвестная география не считается молча разрешённой. Закрепление эндпоинта не отменяет проверки.

Сохраняемый preset: `warpscout-0.16.0-mihomo-1.19.31-awg-v1`. Редактируются только **JC, Jmin, Jmax и I1** (`jc`, `jmin`, `jmax`, `i1` в JSON), с ограниченными диапазонами и проверяемой цепочкой тегов I1. **S1/S2 остаются 0; H1–H4 — 1,2,3,4**: закреплённый WarpScout не умеет передавать произвольные S/H для своего протокола пира. Несовместимые изменения отклоняются; настройка AWG не относится к MASQUE. Точные границы — в [валидации](profile_validation.go). Это совместимость закреплённых инструментов, не поддержка произвольных конфигураций AmneziaWG.

## Обновление

Поведение установщика кандидата описано по исходникам, это не приёмка релиза. Он сохраняет UCI/глобальные настройки, аккаунт и хранилище профилей; первый запуск мигрирует старые секции. Сохраняются закрепления, порты, намерение включения, язык UI (если не переопределён явно), состояние службы и автозапуска. Пустое хранилище не заполняется заново. Маршруты/firewall/сеть/SSClash не меняются, общие бинарники не заменяются.

Для обновления используйте только соответствующий комплект после ревью; скачивание v2.2.0 выше — **не** способ обновить до кандидата. Повторите `--mihomo`/`--warpscout`, если намеренно сохраняете внешние зависимости; без флагов устанавливаются приватные копии из комплекта.

Обновление работающей службы кратковременно прерывает её прокси-соединения. Ранее выключенную службу не следует считать автоматически включённой после обновления. Для ручного управления:

```sh
/etc/init.d/warpd start
/etc/init.d/warpd stop
/etc/init.d/warpd restart
/etc/init.d/warpd enable
/etc/init.d/warpd disable
```

Перед обновлением сохраняйте приватные копии `/etc/config/warpd`, `/etc/warpd/warp-account.json` и `/etc/warpd/profiles.json` вне роутера. Они содержат настройки и ключи, не добавляйте их в Git.

## Удаление

Удаление **кандидата** убирает принадлежащие ему файлы программы/приватные зависимости или ссылки, сохраняя UCI, аккаунт, профили и учётные данные Relay:

```sh
warpd-uninstall
```

Дополнительно удалить известные файлы приватных данных:

```sh
warpd-uninstall --purge
```

Точный список purge кандидата: **`/etc/config/warpd`, `/etc/warpd/warp-account.json`, `/etc/warpd/profiles.json`**. Ключи аккаунта и учётные данные Relay удаляются: при необходимости заранее сделайте копию. Неизвестные файлы сохраняются; `/etc/warpd` удаляется только пустым. Внешние `/usr/bin/warpscout`, `/opt/clash/bin/clash`, SSClash, общие пакеты и сетевые настройки вне области удаления. См. [исходник удаления](packaging/uninstall.sh). Старый uninstaller v2.2.0 появился до хранилища профилей; не приписывайте ему поведение purge кандидата.

После удаления установленная команда удаления исчезает. Повторный запуск из распакованного комплекта — `sh uninstall.sh` — пригоден для идемпотентной проверки/повторного удаления.

## Порты и настройка клиента

После чистой инициализации у кандидата есть только WARP на порту 4001; управление — 9095. Порты дополнительных профилей назначаются/выбираются при создании, а не фиксированы по транспорту. Мигрированные профили сохраняют старые порты. Публичный TCP-порт открывается только после свежего подтверждения готовности/политики. UDP ASSOCIATE и BIND не поддерживаются.

Укажите SOCKS5 `LAN-IP-роутера:4001` в приложении или своей существующей системе маршрутизации. Сам warpd не направляет через себя весь трафик роутера или клиентов. Например, с компьютера:

```sh
curl --proxy socks5h://192.168.10.1:4001 --noproxy '' \
  --connect-timeout 12 --max-time 25 https://ifconfig.co/json
```

`socks5h` передаёт имя назначения SOCKS-серверу. Не используйте `--insecure`: TLS-сертификаты должны проверяться.

## Где хранятся файлы

| Путь | Назначение |
| --- | --- |
| `/usr/bin/warpd` | управление и встроенная веб-панель |
| `/usr/libexec/warpd/mihomo` | собственный движок или явная ссылка на внешний |
| `/usr/libexec/warpd/warpscout` | собственный сканер или явная ссылка на внешний |
| `/etc/init.d/warpd` | служба procd |
| `/usr/sbin/warpd-uninstall` | удаление |
| `/usr/share/warpd/` | метаданные установки |
| `/etc/config/warpd` | глобальные настройки UCI и сохранённый источник миграции |
| `/etc/warpd/profiles.json` | приватное атомарное хранилище профилей/Relay, **0600**, родитель **0700**; содержит учётные данные Relay |
| `/etc/warpd/warp-account.json` | общий приватный аккаунт |
| `/tmp/warpd-mihomo.yaml` | сгенерированная конфигурация с ключами, RAM |
| `/var/run/warpd`, `/var/warpd` | рабочие каталоги, на OpenWrt — RAM |

Старые ручные установки без `/usr/libexec/warpd/` продолжают использовать `/opt/clash/bin/clash` и `/usr/bin/warpscout`. Если собственная установка warpd повреждена, warpd не подменяет её молча общим бинарником.

## UCI и API

Глобальные параметры остаются в `warpd.global`: `enabled`, `check_period`, `scan_sample`, `scan_jobs`, `autoscan_on_start`, `max_ping`, `exclude_nodes`, `exclude_countries`, `fail_restart`, `fail_rescan`, `dme_rescan_gap`, `web_listen`, `web_port`, `web_secret`, `web_language` (`en`/`ru`). Исключения разделены запятыми. Начальный `profile_schema=1` отличает новую схему. После инициализации изменяйте профили через панель или API стабильных ID, не старые слоты UCI (`warpd.warp`, `warpd.masque`, `warpd.masqueh2`, `warpd.m2w`). После внешних правок глобального UCI нужен перезапуск.

Настройки профилей и состояние выполнения читаются отдельно:

```sh
curl -fsS http://192.168.10.1:9095/api/profiles
curl -fsS http://192.168.10.1:9095/api/status
```

Выключить профиль по фактическому `id` из `/api/profiles`, не по имени/типу. Учётных данных в примере нет:

```sh
profile_id='REPLACE_WITH_ID_FROM_API'
curl -fsS -X PATCH -H 'Content-Type: application/json' \
  -d '{"enabled":false}' \
  "http://192.168.10.1:9095/api/profiles/$profile_id"
```

При включённой аутентификации передавайте bearer-токен приватно в заголовке `Authorization`, не в URL или публикуемой команде. CRUD профилей/Relay требует строгий JSON ограниченного размера и `application/json`; неизвестные поля отклоняются. Маршруты: `POST /api/profiles`, `PATCH`/`DELETE /api/profiles/{id}`, `POST /api/relays`, `PATCH`/`DELETE /api/relays/{id}`; DELETE использует JSON `{}`. Явная активация — `POST /api/relays/{id}/activate` с `{}`. Поиск — `POST /api/scan` с `{"for":"<profile-id>"}` или `{"for":"both"}`. Перезапуск затрагивает общий движок, не один профиль.

Старые изменения фиксированных слотов (`/api/proxy`, `/api/endpoint`, `/api/endpoint/clear` и поля слотов в `/api/config`) отклоняются в динамическом режиме. Глобальные настройки UCI остаются отдельно. Ответы различают **`persisted`** и **`applied`**; ошибка применения может вернуть HTTP 503 уже после сохранения желаемого состояния. Даже `applied:true` не означает готовность туннеля. Перечитайте `/api/profiles` и `/api/status`; non-2xx не доказывает откат. Статус содержит `profile_error`, готовность транспорта/политики по ID, `public_listening` и фактическое намерение включения с учётом родителя.

## Ограничения и диагностика

- TCP-шлюзы требуют **свежей проверки транспорта и политики наблюдаемого HTTP-colo**, привязанных к конкретному управляемому процессу, применённой конфигурации/поколению, эндпоинту и настройкам. Обслуживающий colo **не доказывает идентичность/географию туннельного пира или иностранный публичный IP**. Локальные тесты не доказывают реальную географию маршрута.
- Кандидаты проверяются через loopback до публичного доступа. У неподходящего, устаревшего или непроверенного кандидата нет публичного TCP-шлюза. Отзыв/истечение допуска закрывает уже передаваемые потоки и слушающий порт. Это не firewall всего роутера: он не защищает посторонние порты и локальный доступ к loopback-портам кандидатов.
- Публичный SOCKS поддерживает **только TCP CONNECT**, без BIND и UDP ASSOCIATE. Внутренний транспорт MASQUE QUIC не означает поддержку UDP для SOCKS-клиентов.
- Relay-WARP и сохранённый `legacy-m2w` дополнительно требуют независимой свежей проверки иностранного публичного IP. Новые цепочки, реальный иностранный выход, успешная привязка Relay или туннель провайдера не заявлены.
- У туннельных профилей общий движок. Перезапуск/переконфигурация могут прервать другие профили; готовность проверяется заново. Независимый мониторинг Relay остаётся отдельным.
- Конфликт порта, отсутствие CA/аккаунта, неверное время, недоступная сеть и ошибки хранилища/миграции — разные причины, не повод автоматически менять SSClash, firewall или сеть.

Начните с «Диагностика и журнал» и журнала поиска в панели, затем `logread -e warpd`, `/etc/init.d/warpd status` и `/api/status`. Не публикуйте ключи и необработанные активные конфигурации.

## Сборка и тесты

До ревью/приёмки — только локальная разработка; команды не развёртывают и не публикуют сборку. Используйте checkout кандидата: клонирование опубликованной ветки само по себе не подтверждает происхождение кандидата. На Linux-компьютере нужны Python 3 и Go 1.24+; для первого получения зависимостей — HTTPS-доступ к GitHub. Сборка не требует root, Docker, SDK OpenWrt или установленного `apk` на компьютере:

```sh
# Из checkout кандидата:
./build.sh --arch arm64
# Для x86-64:
./build.sh --arch amd64
```

При необходимости задайте `GO=/полный/путь/к/go`. Результат — `dist/warpd-<версия>-linux-<архитектура>.tar.gz` и `.sha256`. Зависимости закреплены по версии и SHA-256; повреждённый кэш не считается доверенным. Исходная временная метка архива управляется `SOURCE_DATE_EPOCH`.

```sh
go test -race -count=1 ./...
go vet ./...
python3 -m unittest discover -s packaging -p '*_test.py'
python3 -m unittest discover -s tools -p 'test_*.py'
```

Это команды проверки, не заявление о запуске полного набора тестов при этой правке README или о готовности релиза по локальным результатам.

DOM-тесты интерфейса: [ui_interaction.README.md](ui_interaction.README.md). Node.js/jsdom нужны только для разработки, не для роутера.

Для проверки реальных файлов установки без запуска сервисов можно использовать отдельный offline-root:

```sh
cd /путь/к/распакованному/комплекту-кандидата
mkdir -p /абсолютный/путь/к/пустому-каталогу
sh install.sh --root /абсолютный/путь/к/пустому-каталогу
sh uninstall.sh --root /абсолютный/путь/к/пустому-каталогу --purge
```

Этот режим не проверяет procd, активацию провайдера или работоспособность туннелей. Имя архива не доказывает публикацию или приёмку. Не указывайте в качестве тестового корня рабочую файловую систему или её системные каталоги.
