# warpd

[English](README.md)

Небольшая панель управления WARP-прокси для OpenWrt: поиск эндпоинтов, независимые переключатели сервисов, проверки доступности и географии выхода. Веб-интерфейс пока на русском языке.

Один процесс Mihomo обслуживает включённые SOCKS5-прокси, WarpScout запускается только для поиска и регистрации. TUN не используется; warpd не добавляет маршруты, правила firewall или прозрачное перенаправление трафика. SSClash не требуется.

> Статус «включён» — настройка, а не подтверждение работоспособности. Подходящий HTTP-colo не гарантирует иностранный публичный IP. Неподходящий выход помечается в интерфейсе, но сама оценка политики не блокирует трафик через доступный SOCKS.

## Возможности

- WARP / AmneziaWG, MASQUE (QUIC), MASQUE H2 и цепочка MASQUE → WARP.
- Отдельное включение и выключение каждого SOCKS-порта с сохранением выбора в UCI.
- Сохранение внутренних зависимостей цепочки при отключённых отдельных WARP/MASQUE.
- Один общий прокси-движок; при выключении всех сервисов он останавливается, панель остаётся доступной.
- Автопоиск, ручное закрепление эндпоинтов, ограничение частоты повторных поисков.
- Раздельные статусы транспорта, политики выхода и независимой проверки публичного IP для M2W.
- Встроенная веб-панель без CDN, внешних шрифтов и Node.js на роутере.

## Требования

- OpenWrt с procd и UCI, Linux `arm64` или `amd64`. Основная проверенная платформа — OpenWrt 25.12.5, `mediatek/filogic`, `aarch64_cortex-a53`.
- Доступ root по SSH, свободные выбранные порты и достаточно места в overlay и `/tmp` для распаковки архива. На OpenWrt `/tmp` занимает RAM. Движок Mihomo — самая большая часть комплекта; установщик проверяет свободное место.
- Системное хранилище доверенных CA (`ca-bundle` или эквивалент) и правильные дата/время для HTTPS. Установщик не меняет репозитории и не устанавливает системные пакеты автоматически.
- Доступ к инфраструктуре Cloudflare для регистрации/туннелей и к HTTPS-сервисам проверок.
- Для скачивания по инструкции ниже нужны `wget` с работающей проверкой HTTPS-сертификатов и `tar` с поддержкой gzip. Не отключайте проверку TLS при ошибках скачивания.
- Для установщика нужны `/bin/sh` и команды `sha256sum`, `cat`, `cp`, `mv`, `chmod`, `mkdir`, `dirname`, `uname`, `id`, `readlink`, `grep`, `wc`, `ls`, `df`, `awk`, `mktemp`, `rm`, `rmdir`, `ln`, `sleep` (обычно доступны через BusyBox), а на роутере также `uci`. Размеры файлов проверяются через `wc -c`, права каталога для отката — через `ls -nd` и `awk`; дополнительные пакеты установщик не добавляет.

Установочный комплект содержит warpd и закреплённые версии WarpScout 0.16.0 и Mihomo 1.19.31. Сторонние компоненты устанавливаются в отдельный каталог warpd, а не поверх бинарников SSClash. Источники и лицензии: [THIRD_PARTY.md](THIRD_PARTY.md).

## Установка

### 1. Скачать, проверить и установить на роутере

В публичном [релизе v2.1.1](https://github.com/LirikKun/warpd-openwrt/releases/tag/v2.1.1) доступны комплекты `linux-arm64` и `linux-amd64`. Аккаунт GitHub, CLI и токен не нужны. Актуальная инструкция установки — этот README в репозитории: существующие архивы 2.1.1 не изменялись и по-прежнему содержат прежний русский README, написанный до публикации репозитория. Для этой инструкции новый релиз не требуется.

Подключитесь как root, заменив пример своим LAN-адресом:

```sh
ssh root@192.168.10.1
```

Выполните весь блок в SSH-оболочке роутера. Он определяет архитектуру, скачивает файлы в новый приватный каталог, проверяет SHA-256 **до распаковки** и останавливается при ошибке. Скачанный код не передаётся потоком в оболочку.

```sh
(
  set -e
  [ "$(id -u)" = 0 ] || { printf '%s\n' 'Run this as root on the router.' >&2; exit 1; }
  case "$(uname -m)" in
    aarch64|arm64) arch=arm64 ;;
    x86_64|amd64) arch=amd64 ;;
    *) printf '%s\n' 'Unsupported architecture: arm64 or amd64 required.' >&2; exit 1 ;;
  esac
  version=2.1.1
  umask 077; workdir=$(mktemp -d /tmp/warpd-install.XXXXXX) && cd "$workdir" || exit 1
  printf 'Temporary directory: %s\n' "$workdir"
  archive="warpd-${version}-linux-${arch}.tar.gz"
  base="https://github.com/LirikKun/warpd-openwrt/releases/download/v${version}"
  wget -O "$archive" "$base/$archive"
  wget -O "$archive.sha256" "$base/$archive.sha256"
  sha256sum -c "$archive.sha256"
  tar -xzf "$archive"
  rm -f "$archive"
  cd "warpd-${version}-linux-${arch}"
  sh install.sh
  printf 'Installation finished. Temporary directory to remove manually: %s\n' "$workdir"
)
```

Сжатый архив удаляется после распаковки, чтобы уменьшить расход RAM. Подоболочка не меняет текущий каталог исходной оболочки; переменная `workdir` после неё не сохраняется. После успешной установки вручную удалите **только точный временный каталог, напечатанный выше**, вместе с распакованным комплектом и контрольной суммой, предварительно проверив путь. При ошибке найдите путь в начальной строке «Temporary directory» и изучите файлы, прежде чем решать, удалять ли их. Не запускайте рекурсивное удаление с пустой или угаданной переменной.

SHA-256 выявляет повреждение, но не подтверждает подлинность издателя: получайте архив и контрольную сумму из доверенного HTTPS-релиза. Установщик проверяет комплект до изменений, устанавливает службу procd и включает её автозапуск при новой установке. Это переносимый установочный архив, не пакет APK/IPK: он не регистрируется в `apk`/`opkg` и удаляется собственной командой ниже.

**Необязательно: внешние зависимости.** Если совместимые бинарники уже установлены и вы не хотите хранить вторую установленную копию, **до выполнения блока** замените его последнюю строку `sh install.sh` на команду ниже. Это альтернативный вариант, а не второй запуск установки:

```sh
sh install.sh \
  --mihomo /opt/clash/bin/clash \
  --warpscout /usr/bin/warpscout
```

В этом режиме warpd создаёт свои ссылки на выбранные исполняемые файлы. Он не перезаписывает и не удаляет их; однако будущая замена внешнего бинарника его владельцем повлияет и на warpd. Не любой старый Clash совместим: нужны MASQUE, AmneziaWG, `dialer-proxy` и соответствующие возможности используемой версии Mihomo.

**Запасной вариант: скачать на компьютере.** Скачайте архив для архитектуры роутера и его `.sha256` из того же релиза и выполните на компьютере `sha256sum -c warpd-2.1.1-linux-arm64.tar.gz.sha256` (для x86-64 замените `arm64` на `amd64`). На роутере создайте приватный каталог командой `umask 077; mktemp -d /tmp/warpd-install.XXXXXX` и запишите напечатанный путь. Скопируйте **оба** файла в этот точный каталог через `scp -O`, например: `scp -O warpd-2.1.1-linux-arm64.tar.gz warpd-2.1.1-linux-arm64.tar.gz.sha256 root@192.168.10.1:/tmp/warpd-install.REPLACE/`, заменив адрес и каталог реальными. `-O` нужен для Dropbear без SFTP. На роутере в подоболочке с `set -e` перейдите в этот каталог, повторите проверку контрольной суммы, затем распакуйте архив, удалите сжатый файл, перейдите в распакованный каталог и выполните выбранную команду установки, как выше. При ошибке проверки не распаковывайте архив. После успеха удалите только точный каталог подготовки.

### 2. Первый запуск

Откройте `http://<LAN-IP-роутера>:9095/`. По умолчанию включён только WARP; остальные сервисы выключены.

На чистой установке аккаунта ещё нет. В панели откройте «Диагностика и журнал» → «Обслуживание аккаунта · опасные действия» → «Новый аккаунт». Подтвердите действие и дождитесь успешной регистрации в журнале. Затем нажмите «Найти для всех», если поиск не начался автоматически. Регистрация и поиск зависят от доступности внешней сети; установленная служба ещё не означает готовый туннель.

Не создавайте новый аккаунт при обычном обновлении: это заменяет общие учётные данные и может прервать соединения всех сервисов.

### Доступ и безопасность

Изначально панель и SOCKS слушают `0.0.0.0`, API-токен пустой. Это вариант для доверенной LAN с корректной существующей политикой firewall, **не безопасная публикация в Интернет**. Установщик не открывает WAN-порты и не меняет firewall. Если LAN недоверенная, до использования ограничьте адреса прослушивания или задайте `warpd.global.web_secret` через UCI; после изменения адреса/порта/токена перезапустите warpd.

Не передавайте токен в URL, не публикуйте `/etc/warpd/warp-account.json` и активный `/tmp/warpd-mihomo.yaml`. Защита от межсайтовых запросов не заменяет аутентификацию и доверенную сеть.

## Обновление

Скачайте новый комплект и запустите его `install.sh` тем же способом. Существующие UCI-настройки и аккаунт сохраняются. При использовании внешних зависимостей повторите флаги `--mihomo`/`--warpscout`, чтобы явно сохранить этот способ размещения; без флагов устанавливаются зависимости из нового комплекта.

Обновление работающей службы кратковременно прерывает её прокси-соединения. Ранее выключенную службу не следует считать автоматически включённой после обновления. Для ручного управления:

```sh
/etc/init.d/warpd start
/etc/init.d/warpd stop
/etc/init.d/warpd restart
/etc/init.d/warpd enable
/etc/init.d/warpd disable
```

Перед обновлением сохраняйте приватную копию `/etc/config/warpd` и `/etc/warpd/warp-account.json` вне роутера. Они содержат настройки и ключи, не добавляйте их в Git.

## Удаление

Удалить программу и её собственные зависимости, сохранив настройки и аккаунт:

```sh
warpd-uninstall
```

Также удалить UCI-конфигурацию и известный файл аккаунта:

```sh
warpd-uninstall --purge
```

`--purge` удаляет ключи аккаунта: заранее сохраните их, если планируете восстановление. Неизвестные пользовательские файлы не должны удаляться рекурсивно вместе с каталогом аккаунта. Внешние `/usr/bin/warpscout`, `/opt/clash/bin/clash`, SSClash и сетевые настройки не относятся к удаляемым файлам.

После удаления установленная команда удаления исчезает. Повторный запуск из распакованного комплекта — `sh uninstall.sh` — пригоден для идемпотентной проверки/повторного удаления.

## Порты и настройка клиента

| Сервис | SOCKS5-порт по умолчанию | После чистой установки |
| --- | --- | --- |
| WARP / AWG | 4001 | включён |
| MASQUE / QUIC | 4003 | выключен |
| MASQUE H2 | 4004 | выключен |
| MASQUE → WARP (M2W) | 4005 | выключен |
| Панель/API | 9095 | доступна при работающей службе |

Укажите SOCKS5 `LAN-IP-роутера:4001` в приложении или своей существующей системе маршрутизации. Сам warpd не направляет через себя весь трафик роутера или клиентов. Например, с компьютера:

```sh
curl --proxy socks5h://192.168.10.1:4001 --noproxy '' \
  --connect-timeout 12 --max-time 25 https://ifconfig.co/json
```

`socks5h` передаёт имя назначения SOCKS-серверу. Не используйте `--insecure`: TLS-сертификаты должны проверяться.

## Где хранятся файлы

| Путь | Назначение |
| --- | --- |
| `/usr/bin/warpd` | управление и встроенная веб-панель |
| `/usr/libexec/warpd/mihomo` | собственный движок или явная ссылка на внешний |
| `/usr/libexec/warpd/warpscout` | собственный сканер или явная ссылка на внешний |
| `/etc/init.d/warpd` | служба procd |
| `/usr/sbin/warpd-uninstall` | удаление |
| `/usr/share/warpd/` | метаданные установки |
| `/etc/config/warpd` | постоянные настройки UCI |
| `/etc/warpd/warp-account.json` | общий приватный аккаунт |
| `/tmp/warpd-mihomo.yaml` | сгенерированная конфигурация с ключами, RAM |
| `/var/run/warpd`, `/var/warpd` | рабочие каталоги, на OpenWrt — RAM |

Старые ручные установки без `/usr/libexec/warpd/` продолжают использовать `/opt/clash/bin/clash` и `/usr/bin/warpscout`. Если собственная установка warpd повреждена, warpd не подменяет её молча общим бинарником.

## UCI и API

Основные параметры находятся в секции `warpd.global`: `enabled`, `check_period`, `scan_sample`, `scan_jobs`, `autoscan_on_start`, `max_ping`, `exclude_nodes`, `exclude_countries`, `fail_restart`, `fail_rescan`, `dme_rescan_gap`, `web_listen`, `web_port`, `web_secret`. Исключения — списки через запятую. Для WARP встроенно исключены DME и RU; страна сканера относится к HTTP-colo, а не гарантированно к публичному IP.

Секции `warpd.warp`, `warpd.masque`, `warpd.masqueh2`, `warpd.m2w` содержат `enabled`, `listen`, `port` и ручные эндпоинты. Для M2W используются `outer_endpoint` и `inner_endpoint`. Пустой ручной эндпоинт означает автоматический выбор. Изменения через UI применяются сразу; после редактирования UCI извне выполните `/etc/init.d/warpd restart`.

Текущее состояние:

```sh
curl -fsS http://192.168.10.1:9095/api/status
```

Включить/выключить отдельный сервис:

```sh
curl -fsS -H 'Content-Type: application/json' \
  -d '{"proxy":"masque","enabled":false}' \
  http://192.168.10.1:9095/api/proxy
```

Ключи: `warp`, `masque`, `masqueh2`, `m2w`. При настроенном токене добавьте заголовок `Authorization: Bearer <token>` — не вставляйте действующий токен в опубликованные примеры. Ответ 200 на переключение означает сохранение и проверенное применение. При ошибке/ожидании API возвращает non-2xx; желаемое состояние уже могло сохраниться — перечитайте `/api/status`, не считайте ошибку доказательством отката.

## Ограничения и диагностика

- Иностранный HTTP-colo и страна публичного IP — разные наблюдения. M2W требует отдельного подтверждения иностранного публичного IP, остальные сервисы оценивают допустимость наблюдаемого узла.
- В проведённых проверках MASQUE/H2 часто попадали в DME, а иностранный M2W-IP не был подтверждён. Проект не обещает зарубежный IP или обход всех ограничений.
- «Сеть доступна» не равно «выход подходит». Неподходящий, но доступный SOCKS может передавать трафик; выключайте сервис, если не хотите его использовать.
- Все сервисы используют общий движок. Его перезапуск разрывает их соединения. Выключение отдельного сервиса не должно выключать остальные, но применение конфигурации может кратковременно влиять на активные туннели.
- Занятый порт, отсутствие CA/аккаунта, неверное время и недоступность внешней сети — отдельные причины ошибок, а не повод автоматически менять SSClash или firewall.

Начните с «Диагностика и журнал» и журнала поиска в панели, затем `logread -e warpd`, `/etc/init.d/warpd status` и `/api/status`. Не публикуйте ключи и необработанные активные конфигурации.

## Сборка и тесты

На Linux-компьютере нужны Python 3 и Go 1.24+; для первого получения зависимостей — HTTPS-доступ к GitHub. Сборка не требует root, Docker, SDK OpenWrt или установленного `apk` на компьютере:

```sh
git clone https://github.com/LirikKun/warpd-openwrt.git
cd warpd-openwrt
./build.sh --arch arm64
# Для x86-64:
./build.sh --arch amd64
```

При необходимости задайте `GO=/полный/путь/к/go`. Результат — `dist/warpd-<версия>-linux-<архитектура>.tar.gz` и `.sha256`. Зависимости закреплены по версии и SHA-256; повреждённый кэш не считается доверенным. Исходная временная метка архива управляется `SOURCE_DATE_EPOCH`.

```sh
go test -race -count=1 ./...
go vet ./...
python3 -m unittest discover -s packaging -p '*_test.py'
python3 -m unittest discover -s tools -p 'test_*.py'
```

DOM-тесты интерфейса: [ui_interaction.README.md](ui_interaction.README.md). Node.js/jsdom нужны только для разработки, не для роутера.

Для проверки реальных файлов установки без запуска сервисов можно использовать отдельный offline-root:

```sh
cd /путь/к/распакованному/warpd-2.1.1-linux-arm64
mkdir -p /абсолютный/путь/к/пустому-каталогу
sh install.sh --root /абсолютный/путь/к/пустому-каталогу
sh uninstall.sh --root /абсолютный/путь/к/пустому-каталогу --purge
```

Этот режим не проверяет procd или работоспособность туннелей. Не указывайте в качестве тестового корня рабочую файловую систему или её системные каталоги.
