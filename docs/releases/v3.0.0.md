# warpd v3.0.0

[Release assets](https://github.com/LirikKun/warpd-openwrt/releases/tag/v3.0.0) · [English guide](../../README.md) · [Русское руководство](../../README.ru.md)

## English

### Changes from v2.2.0

- **Dynamic profiles:** create, edit and delete multiple WARP / AmneziaWG and MASQUE (QUIC/H2) profiles with stable IDs, names, ports, endpoint pins, exclusions and health. Fresh installs create only WARP on 4001; existing empty stores stay empty.
- **Fail-closed public SOCKS gates:** TCP CONNECT opens only after fresh transport/exit-policy checks for the exact managed child and applied configuration. Revocation or expiry closes the listener and accepted streams. Relay-WARP and retained `legacy-m2w` also require independent foreign-egress verification.
- **Relay resources and linked Relay-WARP profiles:** independent IP monitoring/activation, including monitor-only operation without an engine; explicit profile-owned manual or generated tunnel credentials, separate from the shared WARP account. Save, enable, restart, monitoring and routine upgrades never implicitly register provider accounts.
- **Relay DNS compatibility:** destination hostnames resolve inside the tunnel, preserving explicit DNS or using `1.1.1.1` / `1.0.0.1` when absent. Use `socks5h`; client-supplied literal Fake-IP cannot be repaired. IPv6-only DNS requires assigned tunnel IPv6; no address is invented and no direct/system fallback is used.
- **Private persistence and bilingual UI:** atomic private profile/Relay storage, strict JSON API and English/Russian management with separate saved/applied/ready states. One shared Mihomo child serves tunnel profiles; monitoring can run independently.

### Install and upgrade

Use the [installation guide](../../README.md#installation--v300). Assets are `install-warpd.sh`, `install-warpd.sh.sha256`, `warpd-3.0.0-linux-arm64.tar.gz`, `warpd-3.0.0-linux-amd64.tar.gz` and a `.tar.gz.sha256` sidecar for each archive. Verify SHA-256 **before extraction**. The online bootstrap offers missing supported packages only with consent; the inner bundle installer does not download them. Engines are pinned to **Mihomo 1.19.31 / WarpScout 0.16.0**.

**Back up privately off-router before upgrading:** `/etc/config/warpd`, `/etc/warpd/warp-account.json`, and `/etc/warpd/profiles.json` if present. UCI/account, pins, ports, enabled choices, language and service/autostart state are preserved; legacy sections migrate on first start. An existing MASQUE → WARP chain is retained as read-only-settings `legacy-m2w`; **new chains are unavailable**. Downgrading the binary alone does not undo migration.

Shared external binaries are not replaced. **Repeat `--mihomo` / `--warpscout` on upgrade** if keeping explicit external dependencies; otherwise private bundled copies are installed. Updating a running service interrupts its proxy connections. Do not generate a new account for a routine upgrade.

For Relay: create a disabled resource with a private activation URL, source IP/interface and manual same-path acknowledgement → create a disabled linked child → explicitly import/generate that child's credentials → enable parent, then child → wait for fresh health/policy and `public_listening` → use `socks5h` at that profile's port. The acknowledgement is not automatic path/binding proof. To stop both, **disable child before parent**: v3.0.0 blocks child toggles while the parent is off, and parent-off alone retains child enabled intent. See the [runtime guide](../relay-runtime-integration.md#setup-and-safe-shutdown).

### Verification and limits

Reused reviewed-runtime evidence: **800 full Go tests + 800 race tests**, `go vet`, ARM64 build. Bounded **2026-10-19 ARM64 OpenWrt / Filogic 820** acceptance passed fresh Relay-WARP health/public policy, LAN public-SOCKS HTTPS to `example.com` (**200, TLS verified**) and independent `ifconfig.co` geolocation (**DE**). Final DNS acceptance observed **one activation attempt, zero new account-generation actions**; explicit profile generation had passed earlier after optional `outer` metadata compatibility was fixed. System Fake-IP remained active; SSClash settings, router routes/firewall and account material were unchanged. Relay/child were restored off, the public port closed and WARP checks passed.

This is **one bounded provider/path/device result**, not all-provider support, live IPv6 acceptance, an AMD64-router test, sustained stability or every recovery scenario. Provider HTTP 200 alone does not prove binding; serving HTTP-colo is not tunnel-peer identity. [Full verification scope](../../README.md#release-verification).

**Safety:** trusted LAN only by default: management binds `0.0.0.0` with no API token, and public SOCKS has no client authentication. Restrict access; an API token does not protect SOCKS. TCP CONNECT only: **no UDP ASSOCIATE/BIND**. No TUN, route, firewall, router-DNS or SSClash changes. Keep activation URLs, keys, stores, engine YAML and backups private. No license has been chosen for warpd's own code; [third-party obligations](../../THIRD_PARTY.md) still apply.

## Русский

### Изменения относительно v2.2.0

- **Динамические профили:** создание, изменение и удаление нескольких WARP / AmneziaWG и MASQUE (QUIC/H2) со стабильными ID, именами, портами, закреплениями, исключениями и проверками. Чистая установка создаёт только WARP на 4001; пустое хранилище остаётся пустым.
- **Закрытые до проверки публичные SOCKS-шлюзы:** TCP CONNECT доступен только после свежей проверки транспорта/политики для конкретного управляемого процесса и применённой конфигурации. Отзыв/истечение допуска закрывает порт и принятые потоки. Relay-WARP и сохранённый `legacy-m2w` также требуют независимой проверки иностранного выхода.
- **Ресурсы Relay и связанные Relay-WARP:** независимые мониторинг IP/активация, в том числе без движка; явный ручной ввод или генерация собственных учётных данных профиля отдельно от общего WARP-аккаунта. Сохранение, включение, перезапуск, мониторинг и обычное обновление не регистрируют аккаунты неявно.
- **DNS Relay:** имена назначения разрешаются внутри туннеля через явно заданный DNS либо `1.1.1.1` / `1.0.0.1`. Используйте `socks5h`: переданный клиентом готовый Fake-IP исправить нельзя. IPv6-only DNS требует назначенного туннельного IPv6; адрес не выдумывается, прямого/системного fallback нет.
- **Приватное хранилище и двуязычная панель:** атомарное хранение профилей/Relay, строгий JSON API, английский/русский UI с раздельными состояниями сохранения, применения и готовности. Туннельные профили обслуживает один общий Mihomo; мониторинг работает независимо.

### Установка и обновление

Используйте [инструкцию установки](../../README.ru.md#установка--v300). Файлы релиза: `install-warpd.sh`, `install-warpd.sh.sha256`, `warpd-3.0.0-linux-arm64.tar.gz`, `warpd-3.0.0-linux-amd64.tar.gz` и `.tar.gz.sha256` для каждого архива. Проверяйте SHA-256 **до распаковки**. Онлайн-bootstrap предлагает недостающие поддерживаемые пакеты только с согласия; внутренний установщик их не скачивает. Закреплены **Mihomo 1.19.31 / WarpScout 0.16.0**.

**До обновления сохраните приватную копию вне роутера:** `/etc/config/warpd`, `/etc/warpd/warp-account.json` и `/etc/warpd/profiles.json`, если он существует. Сохраняются UCI/аккаунт, закрепления, порты, выбор включения, язык и состояние службы/автозапуска; старые секции мигрируют при первом запуске. Существующая MASQUE → WARP сохраняется как `legacy-m2w` с туннельными настройками только для чтения; **новые цепочки недоступны**. Откат одного бинарника не отменяет миграцию.

Внешние общие бинарники не заменяются. **Повторяйте `--mihomo` / `--warpscout` при обновлении**, если сохраняете внешние зависимости; иначе устанавливаются приватные копии из комплекта. Обновление работающей службы прерывает её прокси-соединения. Для обычного обновления новый аккаунт не нужен.

Для Relay: выключенный ресурс с приватным URL активации, исходным IP/интерфейсом и ручным подтверждением пути → выключенный связанный ребёнок → явный ввод/генерация его учётных данных → включение родителя, затем ребёнка → свежая готовность сети/политики и `public_listening` → `socks5h` на порт профиля. Подтверждение не доказывает путь/привязку автоматически. Выключайте **ребёнка до родителя**: v3.0.0 блокирует переключение ребёнка при выключенном родителе, а выключение только родителя сохраняет выбор включения ребёнка. См. [руководство](../../README.ru.md#ресурсы-relay-учётные-данные-и-работа-туннеля).

### Проверка и ограничения

Ранее полученные результаты проверки кода: **800 полных Go-тестов + 800 race-тестов**, `go vet`, сборка ARM64. Ограниченная приёмка **2026-10-19 на ARM64 OpenWrt / Filogic 820** подтвердила свежую готовность Relay-WARP/политики публичного шлюза, HTTPS из LAN через публичный SOCKS к `example.com` (**200, TLS проверен**) и независимую геолокацию `ifconfig.co` (**DE**). Финальная DNS-приёмка: **одна попытка активации, ноль новых действий генерации аккаунта**; явная генерация профиля прошла раньше после исправления совместимости с необязательными метаданными `outer`. Системный Fake-IP остался; настройки SSClash, маршруты/firewall и данные аккаунтов не изменены. Relay/ребёнок возвращены в выключенное состояние, порт закрыт, проверки WARP пройдены.

Это **один ограниченный результат для конкретных провайдера/пути/устройства**, не всеобщая совместимость, реальная IPv6-приёмка, проверка AMD64-роутера, длительная стабильность или все сценарии восстановления. HTTP 200 провайдера не доказывает привязку; HTTP-colo не доказывает идентичность пира. [Границы проверки](../../README.ru.md#проверка-релиза).

**Безопасность:** по умолчанию только доверенная LAN: управление на `0.0.0.0` без API-токена, публичный SOCKS без аутентификации клиентов. Ограничьте доступ; API-токен не защищает SOCKS. Только TCP CONNECT: **без UDP ASSOCIATE/BIND**. TUN, маршруты, firewall, DNS роутера и SSClash не меняются. URL активации, ключи, хранилища, YAML движка и копии должны оставаться приватными. Лицензия собственного кода warpd не выбрана; [обязательства сторонних компонентов](../../THIRD_PARTY.md) сохраняются.
